DEVICE RUN: the 429 handling on a real screen, against the real limiter (traffic slice 5c, mobile)

Where:   Android emulator Pixel_10a, Expo Go 58.0.5, Metro on its own port (8082) with EXPO_PUBLIC_API_URL passed inline
         (http://127.0.0.1:3100 through adb reverse). The project .env was not touched.
Server:  matinee-server main at 239c545 (PR #24 merged), run locally. It is the server's own src/api/main.ts copied into the
         scratchpad with ONE change: the movie source is a stub, so a search can succeed without TMDB (no TMDB key was used). The
         rate limiter, its policy table, the hold store and the routes are the real ones. Postgres 16 on 54329 and Redis on 6391,
         both throwaway. Dave's own Postgres (5432), Redis (6379), API and Metro were not touched. The server repo stayed clean.
How the limit is reached: with `curl` from the same machine. The emulator reaches the server through adb reverse, so it shares
         the address 127.0.0.1 with curl: this is the "busy shared address" case (a venue's wifi, carrier-grade NAT). Each storm
         is fired at the end of a clock minute, because the limiter's windows are aligned to the minute and a Retry-After
         then is seconds, not nearly a minute. The app's install id in the log is 0ebcd08d-... (shortened below).
Oracle:  the server's request log (policy and scope on every 429; userId = the X-Client-Id the request carried) and Redis.
         Times are UTC, as the server logs them.

POLLING, not touched, checked read-only (no polling file or polling test changed since main):
    poll #1 in a row answers 429: stale-map Toast=true, screen status=ready
    poll #2 in a row answers 429: stale-map Toast=true, screen status=ready
    poll #3 in a row answers 429: stale-map Toast=false, screen status=error

  That is the existing rule (keep the map on 1-2 failed polls, error on the 3rd), run on a 429 error through the unchanged functions.

RUNS I THREW AWAY, and why
  - First launch of the app: "Cannot find native module 'ExpoCrypto'". The emulator booted from a snapshot with an Expo Go process that
    predates the two native modules; force-stopping Expo Go and relaunching fixed it (the same dev-only quirk 5b recorded).
    It matters a little more now: useMovies.ts imports the install-id module, so Home, movie detail and search load expo-crypto and
    expo-secure-store too, where before only the seat screen did. Both are in Expo Go 58.0.5 and were approved in 5b: no new build.
  - A hold run where my tap missed the seat, so Continue stayed disabled and no request was sent: it proved nothing and is not used.
    The runs above check that a seat is really picked before the storm fires.
  - A search run where my curl loop had not yet reached 180 requests, so the app's first search was admitted: not used.

    address" is exactly that, but how Railway presents client addresses is still unproven.
